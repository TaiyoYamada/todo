# 0008 アプリの外への連絡を1か所にまとめ、保存データが変わるたびに行う

- 日付: 2026-10-09
- 状態: 採用。スクリーンタイムの部分は実機で未検証(Claude が決めた。オーナーの確認待ち)

## 状況

アプリ本体は、いまの状況を、アプリの外の3か所へ伝えます。写し(ウィジェットとスクリーンタイムの拡張機能が読む)、ロックの指示(シールドと予約)、通知です。

[0005](0005-screen-time-boundary.md) の時点では、`AppFeature.syncShield` が、`ShieldPlan` が変わったときだけ `shield.apply` と通知の置き換えを呼んでいました。写しは `shield.apply` の実装の中で書いていました。コードレビューで、次の不具合が見つかりました。

- 今日作った目標は、今日はロックしないので `ShieldPlan` が変わらない。写しも予約も更新されず、翌朝のロックが始まらない。ウィジェットも「未設定」のままになる。
- 写しを書いても、ウィジェットに描き直しを頼んでいなかった。
- `ShieldPlan` に今日の分の残り秒数が入っていた。計測中は 15 秒ごとに値が変わり、そのたびに予約をすべて張り直していた。
- 続けて変更が来ると、古い指示が、新しい指示のあとから伝わることがあった。
- アプリを閉じている間は、日付が変わっても、計測が今日の分に達しても、ロックを外すきっかけがなかった。

## 決定

- 外への連絡は、`AppFeature.syncOutside(_:worldChanged:)` の1か所から行う。
- 保存データが変わったら、必ず伝える。時間がたっただけのときは、`ShieldPlan` が変わった場合に限る。
- 伝える順は、写し → ロックの指示 → 通知。続けて変更が来たら古い連絡をやめ(`cancelInFlight`)、段階のあいだで取り消しを確かめる。
- 写しは `SnapshotClient` という依存に分ける。書いたあとに、ウィジェットの描き直しを頼む。`ShieldClient` の実装は写しを書かない。
- `ShieldPlan` には、刻々と変わる値を入れない。残り秒数を外した。必要な側が、写しから自分で計算する。
- 見直しの時刻を足す。`ShieldPlan.wakeTimes` に、計測が今日の分に達する時刻を入れる。`MonitorScheduler` は、1日の開始時刻を毎日予約する。
- 拡張機能は、これまでどおり写しを読む。起こされたら、写しと現在時刻から `LockEngine` で判定し直す。どの予約で起きたかは見ない。

## 理由

- 1か所にまとめると、順序と取り消しをそこだけで守れる。3つがばらばらに動くと、「通知は新しいが、ロックは古い」という食い違いが起きる。
- `ShieldPlan` は、ロックの状態の要約で、写しや予約の中身のすべてではない。何が外に影響するかを1つずつ見分けるより、保存データが変わるたびに伝えるほうが漏れない。保存データが変わるのは人が操作したときなので、回数は多くない。
- 時間がたっただけのときまで毎回伝えると、15 秒ごとに予約を張り直すことになる。予約の張り直しは、不具合の報告が多い操作([リスクの調査](../../research/risks.md))。
- 写しを先に書くのは、予約の時刻に起こされた拡張機能が、最新の状況で判定できるようにするため。
- 拡張機能に「掛ける」「外す」の指示を持たせず、写しから判定させると、予約したあとで状況が変わっても食い違わない。起こされ損ねても、次の機会に正しい状態へ直る。
- 写しを依存に分けると、テストで「何を、どの順で伝えたか」を確かめられる。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 外に影響する値をすべて `ShieldPlan` に入れ、変わったときだけ伝える | 影響する値を漏れなく挙げ続けるのが難しい。実際に漏れた(作った当日の目標) |
| 各画面が、保存のたびに自分で写しを書く | 書く場所が散り、書き忘れが起きる |
| 予約ごとに「掛ける」「外す」を決めておき、拡張機能は写しを読まない | 予約したあとで状況が変わると食い違う。そのたびに張り直しが要る |
| 3つを同時に呼ぶ | 写しが古いうちに、拡張機能が起こされることがある |

## 影響

- 実機では、保存データが変わるたびに、予約をすべて止めて張り直す。問題が出ないかは未検証([公開前の確認事項](../release-checklist.md))。
- 取り消しを確かめるのは、段階のあいだと、通知を1件予約するごと(PR #14 で足した)。写しの書き出しと、ロックの指示は、始めたら最後まで行う。
- 設定でロックするアプリを選び直したときだけは、`SettingsFeature` が `shield.apply` を直接呼ぶ。
- 計測中は、今日の分に達する時刻が秒未満でぶれ、15 秒ごとに連絡し直している。この決定の狙いに反するので、直す必要がある([設計](../architecture.md) 8)。
- 順序、取り消し、伝える条件は、Reducer のテスト(`AppFeatureSyncTests`)で確かめている。
- 0005 の「影響」に書いた、直すと分かっていた2点は、この決定で直した。
