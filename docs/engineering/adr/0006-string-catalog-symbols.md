# 0006 文言は String Catalog に置き、生成されたシンボルで参照する

- 日付: 2026-10-09
- 状態: 採用(Claude が決めた。オーナーの確認待ち)

## 状況

日本語と英語に対応します([仕様](../../product/spec.md) 7)。文言はコードに直書きしない約束です。

文言をキーの文字列で参照すると、打ち間違いや、消したキーへの参照が、実行するまで分かりません。画面にキーがそのまま出る、という形で気づくことになります。

## 決定

- 文言は `Packages/TodoKit/Sources/AppFeature/Resources/Localizable.xcstrings` の1ファイルに置く。
- キーは、画面と意味を表す、ドット区切りの名前にする(例: `today.slack.label`)。英語の文そのものをキーにしない。
- コードからは、Xcode がカタログから生成するシンボルで参照する(例: `Text(.todaySlackLabel)`)。
- 元の言語は英語。日本語と英語の両方を必ず入れる。
- 時間の長さ、時刻、日付、曜日は文言にせず、書式(`Duration` や `Date` の `formatted`)に任せる。

## 理由

- キーの打ち間違いと、消したキーへの参照が、コンパイルエラーになる。
- 引数のある文言が関数になる(例: `.todayCtaStartFocus(goal.title)`)。引数の数と型の間違いも、コンパイル時に分かる。
- キーを意味の名前にすると、英語の文を直しても、キーと日本語の訳はそのまま残る。
- 1ファイルにまとめると、訳の抜けを Xcode のカタログ画面で一覧できる。
- 書式に任せた部分は、言語ごとの語順や単位を自分で持たずに済む。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 英語の文をそのままキーにする(`Text("Add")`) | 英語の文を直すとキーが変わり、訳が外れる。同じ英語で訳が違う場面を区別できない |
| キーを文字列で書く(`Text("today.slack.label")`) | 打ち間違いが実行時まで分からない |
| SwiftGen などの外部の生成ツール | Xcode に同じ機能がある。依存を増やさない |

## 影響

- シンボルを生成するのは Xcode のビルド。`Configs/Base.xcconfig` で `STRING_CATALOG_GENERATE_SYMBOLS = YES` にしている。
- カタログのキーは、手で管理する扱い(`extractionState` が `manual`)にする。コードから自動で拾われたキーではない。
- キーを足した直後は、一度ビルドするまでシンボルが補完に出ない。
- キーの名前を変えると、シンボルの名前も変わり、参照している場所がコンパイルエラーになる。これは意図した動き。
- 文言カタログは `AppFeature` にある。拡張機能やウィジェットを足すときは、それぞれのターゲットに文言を置くか、共有の置き場を作るかを決める。
- 見本データの目標名とタスク名はカタログに入れていない。`SampleData` の中で端末の言語を見て切り替えている。
- キーからシンボルへの変換の規則と、文言を足す手順は[開発の手順](../development.md)にある。
