# 技術的な決定の記録(ADR)

技術的な決定を、1つにつき1ファイルで残します。あとから「なぜこうなっているのか」を確かめるためのものです。
仕様に関する決定は、ここではなく[決定の記録](../../product/decision-log.md)に書きます。

## いつ書くか

- 外部ライブラリを足す、または外すとき
- モジュールの分け方や、データの流れを変えるとき
- あとから変えにくい決定をするとき(保存の形式、拡張機能との受け渡しなど)

小さな実装の選択は書きません。迷ったら、「半年後の自分が理由を知りたくなるか」で決めます。

## 書き方

- ファイル名は `<4桁の番号>-<英小文字とハイフンの短い名前>.md`。番号は続きを使う。
- 60 行を目安に短く書く。細かい手順は[設計](../architecture.md)や[開発の手順](../development.md)に置き、ここからリンクする。
- 決定を変えるときは、古い ADR を書き換えない。新しい ADR を足し、古いほうの状態を「0010 で置き換え」のように直す。
- 確かめていないことは、そのとおり書く。

## ひな形

```markdown
# <番号> <決定を1文で>

- 日付: YYYY-MM-DD
- 状態: 提案 / 採用 / 却下 / <番号> で置き換え(誰が決めたか)

## 状況

何を決める必要があったか。前提と制約。

## 決定

何をするか。箇条書きで具体的に。

## 理由

なぜそれを選んだか。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
|  |  |

## 影響

この決定で増える手間、できなくなること、未検証の点、やめるときの退路。
```
