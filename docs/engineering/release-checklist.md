# 公開前の確認事項

最終更新: 2026-10-09

App Store に出すまでに済ませることの一覧です。**いまは、どれも済んでいません。**
根拠の多くは[リスクの調査](../research/risks.md)にあります。Apple の手続きや審査の基準は変わるので、着手するときに公式の情報で確かめ直してください。

課金や申請を伴う操作は、オーナーが行います(Claude は指示なしに行いません)。

## 先にやること(待ち時間が長い順)

| 順 | すること | 理由 |
|---|---|---|
| 1 | Apple Developer Program に登録する | 以降のすべての前提 |
| 2 | 名前と識別子を決める | 権限の申請は識別子ごと。あとから変えるとやり直しになる |
| 3 | Family Controls の配布用の権限を申請する | 承認まで数日のことも、2か月近く応答がないこともある。公開日を決める前に出す |
| 4 | ロックを実機で確かめる | 一番不確かな部分。コードは一度も実機で動かしていない。数週間の連続動作を見る |
| 5 | 料金、文言、画像、審査用のメモをそろえる | 3 と 4 を待つ間に進められる |

承認を待つ間に、ロックを使わない「予報だけ」の版を先に出す案があります([批評と強化案](../research/critique-and-ideas.md) 強化案 5)。出すかどうかは決まっていません。出す場合の注意は 13 に書きます。

## 1. Apple Developer Program

- [ ] Apple Developer Program(有料)に登録する
- [ ] App Store Connect で、契約、税金、口座の情報を入れる(有料にする場合は有料アプリの契約が要る)
- [ ] Small Business Program に申し込むかを決める

## 2. 名前と識別子

- [ ] アプリ名を決める。いまの「Lockcast」は仮で、法的な確認をしていない(8 を参照)
- [ ] App Store Connect にアプリのレコードを作り、その名前が取れるかを確かめる
- [ ] 識別子を決める。いまは `com.taiyoyamada.todo`(開発用は末尾に `.dev`)。**公開後は変えられない**
- [ ] 拡張機能の識別子を確かめる。いまは本体の識別子に `.widgets`、`.shield-monitor`、`.shield-configuration` を付けたもの
- [ ] App Group を登録する。いまの設定は `group.com.taiyoyamada.todo` と `group.com.taiyoyamada.todo.dev`
- [ ] 版の番号を決める。いまは 0.1.0(`Configs/Base.xcconfig`)

## 3. Family Controls の配布用の権限

開発用の権限は Xcode で使えますが、配布(TestFlight と App Store)には Apple の個別の承認が要ります。

- [ ] アプリ本体の識別子で申請する
- [ ] **Family Controls を使う拡張機能の識別子ごとに申請する。** いまは `.shield-monitor` と `.shield-configuration` の2つ(ウィジェットは使っていない)。本体が承認されても、拡張機能のぶんが別に止まるという報告がある
- [ ] 開発用の版(`.dev`)を TestFlight で配るなら、その識別子でも申請する
- [ ] 申請文には「本人が、自分の端末で、自分の使い方を管理する」用途だと明記する。他人の監視や追跡と読める表現を避ける
- [ ] 申請文、審査用のメモ、ストアの説明文の内容をそろえる
- [ ] 承認されたら、署名したビルドに権限が入っていることを確かめる

所要期間は示されていません。調査で見つかった報告は、数日以内、約 3 週間、2 週間応答なし、4 週間応答なし、2 か月近く応答なし、です。

## 4. 実機で確かめる前に直すもの

ロックのコードはそろっていますが、コードを読んだ時点で、直すと分かっている点があります([設計](architecture.md) 8)。

- [ ] 写し、予約、通知が、保存データの変更のたびに更新されるように直す(いまは `ShieldPlan` が変わったときだけ。作った当日の目標が、翌朝のロックに間に合わない)
- [ ] ロック中の計測で、予約を 15 秒ごとに張り直さないように直す
- [ ] 写しを書いたあとに、ウィジェットの更新を頼む
- [ ] 計測が、アプリを閉じている間に今日の分へ達したとき、ロックを外すきっかけを用意する
- [ ] ロック画面のボタンを押したときの動きを決める。必要なら、シールドの操作の拡張機能を作る
- [ ] 設定アプリで許可を切られたときの動きを決める(いまは、設定と初回設定の画面でしか許可の状態を見ていない)
- [ ] 実機向けに署名し、アプリ本体と3つの拡張機能が入ることを確かめる

## 5. スクリーンタイムの実機検証

シミュレータでは確かめられません。開発機だけでなく、**普段使いの実機で数週間**続けて見ます。結果は[仕様](../product/spec.md)の「未検証の部分」に反映します。

許可と選択

- [ ] 許可を求める画面が出て、許可、拒否のどちらでも先へ進める
- [ ] 選んだアプリ、カテゴリ、Web サイトが、アプリを起動し直しても残る
- [ ] アプリを 50 個より多く選んだときにロックが効くか(効かないという報告がある。多いときはカテゴリで選ばせる)
- [ ] 設定アプリで許可を切ったあと、アプリがどう振る舞うか

ロックの開始と解除(アプリを開いている間)

- [ ] 着手リミットを過ぎたタスクを足すと、すぐにロックされる
- [ ] タスクを完了、または取り下げると外れる
- [ ] 集中の計測が今日の分に達した時点で外れる
- [ ] パスを使うと外れ、15 分後に戻る
- [ ] 理由が複数あるとき、すべて片づくまで外れない

ロックの開始(アプリを閉じている間)

- [ ] 「朝から」の目標で、1日の開始時刻(初期値 4:00)にロックされる
- [ ] 「時刻を指定」の目標で、その時刻にロックされる
- [ ] タスクの着手リミットの時刻にロックされる(1 回きりの予約)
- [ ] パスが切れた時刻に、アプリを開かなくてもロックに戻る
- [ ] 作った当日の目標が、翌日の朝にロックされる(アプリを一度も開かなくても)
- [ ] 計測中にアプリを閉じ、今日の分に達した時刻を過ぎたとき、いつ外れるか(いまの作りでは、アプリを開き直すまで外れない見込み)
- [ ] 予約の区間(15 分)が 0 時や1日の開始時刻をまたぐとき
- [ ] 予約の数が OS の上限(20 件)を超えないこと。目標のロック開始時刻が多いとき、タスクが多いとき

長く使ったとき、環境が変わったとき

- [ ] 数週間、毎日ロックが始まり続ける(拡張機能が数日で止まるという報告がある)
- [ ] 端末の再起動のあと
- [ ] タイムゾーンの変更、夏時間の切り替え、端末の時刻を手で変えたとき
- [ ] 予定どおりにロックが始まらなかったとき、次にアプリを開いた時点で正しい状態に直る
- [ ] アプリを削除すると、ロックが残らない
- [ ] 開発用と本番用の両方を同じ端末に入れたとき、互いに干渉しない
- [ ] 対応する最も古い OS(iOS 26.0)と、その時点で最新の OS の両方

拡張機能

- [ ] 監視の拡張機能が、写し(`snapshot.json`)を読んで判定できる。メモリの制限で落ちない
- [ ] ロック画面に、片づけるものの名前と残りが正しく出る。日本語と英語
- [ ] 写しが読めないとき、ロック画面に決まった文言が出る
- [ ] ロック画面のボタンが、決めたとおりに動く

ウィジェット、Live Activity、通知(スクリーンタイムではないが、実機でも見る)

- [ ] ウィジェットが、アプリ本体の書いた写しを読める(App Group)。ホーム画面とロック画面の両方
- [ ] ウィジェットの内容が、ロックの状態の変わり目で切り替わる。アプリで操作したあと、古い内容が残らない
- [ ] 集中の Live Activity が、開始で出て、終了で消える。Dynamic Island のある機種とない機種
- [ ] 通知が、ロックの 30 分前と開始時に届く。許可しなかったときも、ほかが動く

未成年の端末

- [ ] ファミリー共有の子どもアカウント(13〜17 歳)の端末で、本人の許可でロックまで通るか。通らない場合、対象の年齢を見直す

## 6. 審査に向けた準備

スクリーンタイムを使うアプリで論点になる条項です(出典は[リスクの調査](../research/risks.md) 5)。

| 条項 | 気をつけること |
|---|---|
| 2.5.1 | API を意図された用途で使う。審査用のメモに、何を、いつ、なぜロックするかを書く |
| 4.10 | スクリーンタイム API そのものを課金の境目にしない(7 を参照) |
| 4.3(b) | 同種のアプリが多い。ロック予報と、締切からの逆算を前面に出して違いを示す |
| 2.3.1 | ない機能を宣伝しない。「絶対に解除できない」と書かない |
| 2.3.7、5.2.1 | ほかのアプリの名前や商標を、名前、キーワード、説明に入れない |
| 1.4.1 | 診断や治療と読める表現をしない(10 を参照) |
| 5.1.1 | 集めるデータと用途を正しく示す |

- [ ] 審査用のメモを書く。本人が自分を管理する用途であること。ロックの条件。データは端末の外に出ないこと
- [ ] 審査する人がロックを再現できる手順を書く(例: 締切が近いタスクを足すと、すぐにロックされる。完了にすると外れる)
- [ ] アカウント登録がないので、審査用のアカウントは不要と書く
- [ ] 年齢区分の質問に答える
- [ ] 輸出コンプライアンスの質問に答える(独自の暗号は使っていない。`Info.plist` に答えを書いておくかを決める)
- [ ] サポート用の URL を用意する

## 7. 料金

**決まっていません。オーナーが決めます。**

調査の推奨は、フリーミアムです([事業モデル](../research/business-model.md))。ロックと予報は無料。件数、取り込み、統計を Pro(年 ¥2,900、または買い切り ¥6,800)にする案です。

- [ ] 無料か、有料か、フリーミアムかを決める
- [ ] 有料にする場合、無料の範囲と価格を決める。ロックできるかどうか自体は課金の境目にしない(4.10)
- [ ] 有料にする場合、課金の実装(StoreKit)、購入の復元、価格の表示を作る。**いまは何もない**
- [ ] サブスクにする場合、継続して価値を出せるかを考える(3.1.2(a))。難しければ買い切りにする
- [ ] パスの追加販売はしない(調査の推奨。使う人が負けるほど儲かる形になるため)

## 8. 名前、商標、権利

**ここに書くことは法的な助言ではありません。** 開発者による簡易な確認の手順です。出願や公開の前に、弁理士などの専門家に確かめてください。

- [ ] J-PlatPat(特許庁の検索)で「Lockcast」「ロックキャスト」と、似た読みの商標を調べる。**まだ調べていない**
- [ ] 米国でも出すなら、米国の商標も調べる
- [ ] 日米の App Store で、同じ名前や紛らわしい名前のアプリがないかを、公開の直前にもう一度調べる(2026-10-09 の簡易な検索では、完全一致は見つからなかった)
- [ ] 商標を出願するかを決める
- [ ] 特許は調べていない。締切から逆算してロックする仕組みや、ロックまでの残りを見せる画面が、他者の特許に触れないとは確認できていない。気になる場合は専門家に相談する
- [ ] ほかのアプリの名前、画面、文言、アイコンをまねない
- [ ] いまのアプリアイコンは、画像生成で作った仮のもの。そのまま使うなら、使った道具の利用条件と、ほかのアイコンや商標に似ていないかを確かめる
- [ ] アプリアイコンに SF Symbols を使わない(Apple の利用条件で禁じられている)
- [ ] 使っているライブラリのライセンス表示を、アプリの中に用意する。**いまはない**。直接使っているのは TCA、SQLiteData、swift-dependencies、GRDB(いずれも MIT)。間接的に入るものも確かめる
- [ ] Apple の商標(「スクリーンタイム」など)の書き方を、Apple の指針に合わせる

## 9. プライバシー

- [ ] プライバシーポリシーを書き、URL を用意する(App Store Connect で必須)
- [ ] App Store の「App のプライバシー」に答える。いまの実装は、データを端末の外に送らない。解析やクラッシュ報告の仕組みも入れていない。あとで足したら、答えも直す
- [ ] 説明文に「端末内だけ」と書くなら、実際にそうであることを保つ
- [ ] プライバシーマニフェスト(`PrivacyInfo.xcprivacy`)が要るかを確かめる。`UserDefaults` を使っている。アプリ本体と拡張機能のそれぞれで確かめる
- [ ] 通知の許可を求める理由が、画面の流れで伝わるかを確かめる(いまは初回設定を終えた直後に求める)
- [ ] 選んだアプリの情報が、端末の外に出ないこと(Apple の仕組みで、アプリからは中身が見えないトークンとして扱われる)を説明に書く

## 10. 文言

アプリの中と、ストアの説明の両方に当てはめます。

| 使わない | 代わりに |
|---|---|
| 「依存症を治す」「ADHD に効く」など、診断や治療と読める表現 | 「使いすぎ」「先延ばし」「習慣」 |
| 「改善効果◯%」など、根拠のない数字 | 数字を出すなら出典を付ける |
| 「絶対に解除できない」 | 抜け道があることを隠さない |
| 罪悪感や不安をあおる表現 | 何をすればよいかを伝える |
| ほかのアプリの名前 | 使わない |

- [ ] 「ドパガキ」向けという打ち出しを見直す。あとスマとドパロックが先に使っている。他人に向けると揶揄になる言葉でもある。看板は「締切から逆算してロック」「ロック予報」にする案がある(未決定)
- [ ] アプリの中の文言を、上の表で見直す(日本語と英語)

## 11. 画像と多言語

- [ ] アプリアイコンを仕上げる。いまは仮のもの(1024 px の画像1枚。画像生成による)。ダーク、色付きの表示も確かめる
- [ ] スクリーンショットを、日本語と英語で用意する。大きさの要件は App Store Connect で確かめる
- [ ] 撮影には見本データを使う(`-sampleData locked` / `countdown` / `free`)。時刻の表示は `xcrun simctl status_bar booted override --time 9:41` で固定できる
- [ ] ストアの名前、副題、説明、キーワードを、日本語と英語で書く
- [ ] 文言に、訳の抜けがない(2026-10-09 時点で、画面 156 件、ウィジェット 17 件、ロック画面 5 件。抜けなし)
- [ ] Dynamic Type、VoiceOver、「視差効果を減らす」で主要な画面を確かめる
- [ ] 長い目標名、長い英語の文言で、表示が崩れない

## 13. 「予報だけ」の版を先に出す場合

出すかどうかは決まっていません。出すなら、上の 3〜5 を待たずに進められますが、次のことが要ります。

- [ ] 実機でもスクリーンタイム API を呼ばない切り替えを作る。いまは、実機なら必ず本物を呼ぶ
- [ ] Family Controls の権限と、スクリーンタイムの2つの拡張機能を、その版のビルドから外す。権限が入ったままでは、承認なしに配布できない
- [ ] 初回設定と設定の「ロックするアプリ」など、ロックを前提にした文言と画面を外す
- [ ] ロックの前の通知(30 分前と開始時)とウィジェットが、ロックなしでも役に立つかを確かめる。通知の文言は「ロックが始まりました」となっているので、この版に合わせて直す
- [ ] ストアの説明に、ロックしないことをはっきり書く(2.3.1)
- [ ] あとでロックを足すときに、識別子と保存データをそのまま引き継げるようにする
