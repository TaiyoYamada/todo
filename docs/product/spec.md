# 仕様

最終更新: 2026-10-09

このアプリの振る舞いを定める文書です。コードと食い違ったときは、どちらが正しいかを確認してから直します。決定の経緯は [decision-log.md](decision-log.md) にあります。

アプリ名は仮に **Lockcast** としています。lock(ロック)と forecast(予報)を合わせた名前です。当初の仮称 Yoyu(余裕)は、同じ名前のアプリが App Store に3本あったため変えました。商標は未調査です。

どこまで実装できているかは、末尾の「10. 実装の状況」にまとめています。

## 1. 何のためのアプリか

**後回しにしてきた大事なことを、スマホが止まる前に終わらせるアプリ**です。

対象は、時間がゲームやショート動画に流れてしまう人です。次のような状態を想定しています。

- 締切が今日か明日のものはやるが、締切の遠いもの(院試の勉強、TOEIC など)は永遠に後回しになる
- 締切のあるものも、ぎりぎりまで手を付けない
- 毎日の計画を立てるのは面倒で続かない
- 勉強が嫌いなわけではなく、始めるのが面倒
- 気づくとゲームや動画で1時間たっている

通知は無視できますが、ロックは無視できません。このアプリは、決めたことが終わっていないときに、選んだアプリを開けなくします。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 目標 | 締切が遠い大事なこと。「1日の量(分)」と「やる曜日」を持つ |
| 今日の分 | ある目標について、今日やると決めた量 |
| タスク | 締切のあるやること。「締切」と「見積もり(かかる時間)」を持つ |
| 倍率 | 見積もりに掛ける数。人は時間を短く見積もるので、その分を見込む。初期設定では実績から自動で決まる |
| 着手リミット | これ以上遅らせると間に合わない時刻。締切 −(見積もり × 倍率) |
| ロック | 選んだアプリ(ゲーム、動画など)が開けない状態 |
| 余裕 | 次のロックが始まるまでの残り時間。このアプリの中心となる数字 |
| ロック予報 | 今日、何がいつロックの理由になるかを時刻順に並べたもの |
| 集中 | 目標の今日の分を進めるための時間計測 |
| パス | ロックを一時的に外す非常口。回数に上限がある |
| 1日 | 朝4時から翌朝4時まで(設定で 0〜8 時に変更できる) |

## 3. ロックの規則

ロックの理由は2種類あります。理由が1つでも残っている間、ロックは続きます。

### 3.1 目標によるロック

- 今日がその目標の「やる曜日」で、今日の分が終わっていなければロックの理由になる
- **目標を作った当日は、ロックの理由にならない。** 登録した瞬間にスマホが止まると、最初の体験が罰になるため。ロックは次の日から始まる
- ロックが始まる時刻は目標ごとに選べる
  - **朝から**(初期値): 1日の開始からロックする
  - **時刻を指定**: その時刻までに終わっていなければロックする
- 集中の合計が今日の分に達したら、その理由は消える。計測中のぶんも数えるので、止めなくても達した時点で消える
- 今日の分は分割して進めてよい。途中でやめても、やった分は記録に残る(5秒に満たない計測は、押し間違いとして残さない)
- 今日の分に達すると、計測は自動で止まる。そのあと続けて計ることもできる
- 計測中にアプリを閉じても、計測は続く。次に開いたとき、達した時刻で止まったものとして記録する
- 1日の量は 5〜240 分、初期値は 30 分

### 3.2 タスクによるロック

- 未完了のタスクは、着手リミットを過ぎた時点でロックの理由になる
- 完了にするか、取り下げるまで続く。締切を過ぎても同じ
- 着手リミットをすでに過ぎているタスクを足すと、すぐにロックされる。追加の画面でそのことを知らせる
- 完了は自己申告。完了にするとき、**実際にかかった時間を1問だけ聞く。** 選択肢は見積もりの 0.5 / 1 / 1.5 / 2 / 3 倍。これが完了の確認を兼ねる
- 完了にしたタスクは、未完了に戻せる。戻すと、答えた時間も消える

着手リミットに使う倍率は、次のように決まります。

| 設定 | 倍率 |
|---|---|
| **自動**(初期値) | 直近 10 件の完了タスクについて「実際 ÷ 見積もり」を求め、その中央値を使う。実績が 3 件に満たない間は 1.5。1.0〜3.0 の範囲に収める |
| 固定 | 1 / 1.25 / 1.5 / 2 から選ぶ |

- 自動でも、1.0 より小さくはしない。見積もりより早く終わる人でも、着手リミットを後ろへはずらさない
- 倍率が変わると、未完了のタスクすべての着手リミットが動く
- いまの倍率は、設定、タスクの編集、振り返りの画面に表示する

### 3.3 ロックが外れたあと

- 理由がすべて消えたら、その日は自由に使える
- 新しい理由(別のタスクの着手リミットなど)が来たら、またロックされる

### 3.4 パス(非常口)

- 1回につき15分、ロックが外れる
- 1週間(月曜始まり)に使える回数の初期値は2回。設定で0〜5回
- 使えるのはロック中だけ
- 使うときは、ボタンを3秒押し続ける。うっかり使わせないため
- 今週使った回数は振り返りに表示する

### 3.5 抜け道と、その扱い

| 抜け道 | 現在の扱い |
|---|---|
| 完了ボタンを押すだけで外れる | 実際にかかった時間を1問聞くのみ。使ってみてから対策を考える |
| 目標の量を減らす、今日の曜日を外す | 未対応。変更はすぐに効く。「変更は翌日から有効」にする案がある |
| 目標を削除する、削除して作り直す | 削除は長押しを要求するのみ。作り直すと、その日はロックされない。未対応 |
| タスクを取り下げて外す | 取り下げは長押しを要求し、振り返りに回数(直近30日)を出す |
| タスクを削除して外す | 削除は長押しを要求するのみ。取り下げの回数には数えない。未対応 |
| 設定を緩める(パスの回数を増やす、倍率を下げる) | 未対応。変更はすぐに効く |
| 設定アプリで権限を切る | 防げない(iOS の仕様) |

## 4. 余裕の表示(このアプリの中心)

ホーム画面の主役は ToDo の一覧ではなく、**次のロックまでの余裕**です。

- ロックされていないとき: 余裕を秒まで数えて出し、次に何が何時にロックの理由になるかを添える。残り1時間を切ると、色で緊張を伝える
- ロック中: 何を終えれば外れるかと、残りの量を出す。ほかにも理由があれば件数を出す
- パスを使っている間: パスが切れるまでの残り時間を出す
- 今日これ以上ロックの予定がないとき: 「今日は自由」と、次のロックの時刻を出す
- まだ何も登録していないとき: 最初の目標を足すよう促す
- 今日のロック予定を時刻順に並べた「ロック予報」を出す。済んだもの、いま有効なもの、これからのものを区別する

余裕を見せる狙いは、ロックされてから動くのではなく、**ロックされる前に片づける**行動を引き出すことです。理想は、一度もロックされない日が続くことです。

同じ情報を、ウィジェットと Live Activity でアプリの外にも出します(未実装)。ロックの前に通知で知らせることも予定しています(未実装)。

## 5. 画面

| 画面 | 内容 |
|---|---|
| 今日 | 余裕、ロック予報、今日の分、着手リミットが近いタスク(4件まで) |
| 集中 | 全画面の計測。残り時間、目標名、終了時の演出 |
| 予定 | 目標とタスクの一覧、追加、編集、片づけたタスク(直近20件) |
| タスクの完了 | 実際にかかった時間を聞く |
| 振り返り | 今週の集中時間と先週との差、直近14日の日ごとのグラフ、見積もりの癖(いまの倍率)、直近30日のタスク(ロックの前に完了、後に完了、取り下げ)、今週のパス |
| 設定 | 見積もりに掛ける倍率、パスの回数、1日の開始時刻、はじめの説明をもう一度見る。ロックするアプリの選択は未実装 |
| 初回設定 | 導入、仕組みの説明、最初の目標、スクリーンタイムの許可、完了。ロックするアプリを選ぶ画面は未実装 |

## 6. 演出の方針

ゲームやショート動画に慣れた人が相手なので、地味な管理画面にはしません。

- 力を入れる瞬間: 今日の分を終えたとき、ロックが外れたとき、ロックされる前にタスクを終えたとき
- 使うもの: 動き、振動、色の変化、数字の増減
- 使わないもの: ガチャ的な報酬、連続記録が途切れる不安をあおる表現、罪悪感をあおる文言

このアプリ自体がもう1つの依存先になることは避けます。開いている時間が短いほど良いアプリです。
