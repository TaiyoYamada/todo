# 仕様

最終更新: 2026-10-09

このアプリの振る舞いを定める文書です。コードと食い違ったときは、どちらが正しいかを確認してから直します。決定の経緯は [decision-log.md](decision-log.md) にあります。

アプリ名は仮に **Lockcast** としています。lock(ロック)と forecast(予報)を合わせた名前です。当初の仮称 Yoyu(余裕)は、同じ名前のアプリが App Store に3本あったため変えました。商標は未調査です。

どこまで実装できているかは、末尾の「10. 実装の状況」にまとめています。

## 1. 何のためのアプリか

**後回しにしてきた大事なことを、スマホが止まる前に終わらせるアプリ**です。

対象は、時間がゲームやショート動画に流れてしまう人です。次のような状態を想定しています。

- 締切が今日か明日のものはやるが、締切の遠いもの(院試の勉強、TOEIC など)は永遠に後回しになる
- 締切のあるものも、ぎりぎりまで手を付けない
- 毎日の計画を立てるのは面倒で続かない
- 勉強が嫌いなわけではなく、始めるのが面倒
- 気づくとゲームや動画で1時間たっている

通知は無視できますが、ロックは無視できません。このアプリは、決めたことが終わっていないときに、選んだアプリを開けなくします。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 目標 | 締切が遠い大事なこと。「1日の量(分)」と「やる曜日」を持つ |
| 今日の分 | ある目標について、今日やると決めた量 |
| タスク | 締切のあるやること。「締切」と「見積もり(かかる時間)」を持つ |
| 倍率 | 見積もりに掛ける数。人は時間を短く見積もるので、その分を見込む。初期設定では実績から自動で決まる |
| 着手リミット | これ以上遅らせると間に合わない時刻。締切 −(見積もり × 倍率) |
| ロック | 選んだアプリ(ゲーム、動画など)が開けない状態 |
| 余裕 | 次のロックが始まるまでの残り時間。このアプリの中心となる数字 |
| ロック予報 | 今日、何がいつロックの理由になるかを時刻順に並べたもの。目標の今日の分と、今日のうちに着手リミットが来るタスクを、1本にまとめて出す |
| 着手 | タスクに取りかかること。「いま始める」を押すと、その時刻を残す |
| 集中 | 目標の今日の分を進めるための時間計測 |
| パス | ロックを一時的に外す非常口。回数に上限がある |
| 1日 | 朝4時から翌朝4時まで(設定で 0〜8 時に変更できる) |

## 3. ロックの規則

ロックの理由は2種類あります。理由が1つでも残っている間、ロックは続きます。

### 3.1 目標によるロック

- 今日がその目標の「やる曜日」で、今日の分が終わっていなければロックの理由になる
- **目標を作った当日は、ロックの理由にならない。** 登録した瞬間にスマホが止まると、最初の体験が罰になるため。ロックは次の日から始まる
- ロックが始まる時刻は目標ごとに選べる
  - **朝から**(初期値): 1日の開始からロックする
  - **時刻を指定**: その時刻までに終わっていなければロックする
- 集中の合計が今日の分に達したら、その理由は消える。計測中のぶんも数えるので、止めなくても達した時点で消える
- 今日の分は分割して進めてよい。途中でやめても、やった分は記録に残る(5秒に満たない計測は、押し間違いとして残さない)
- 今日の分に達すると、計測は自動で止まる。そのあと続けて計ることもできる
- 計測中にアプリを閉じても、計測は続く。次に開いたとき、達した時刻で止まったものとして記録する
- 1日の区切りをまたいだ計測は、区切りで分けて記録する。区切りより後のぶんは、新しい日の分として数える
- 1日の量は 5〜240 分、初期値は 30 分

### 3.2 タスクによるロック

- 未完了のタスクは、着手リミットを過ぎた時点でロックの理由になる
- 完了にするか、取り下げるまで続く。締切を過ぎても同じ
- 着手リミットをすでに過ぎているタスクを足すと、すぐにロックされる。追加の画面でそのことを知らせる
- 完了は自己申告。完了にするとき、**実際にかかった時間を1問だけ聞く。** 選択肢は見積もりの 0.5 / 1 / 1.5 / 2 / 3 倍(5 分刻みに丸める)。これが完了の確認を兼ねる
- 完了にしたタスクは、未完了に戻せる。戻すと、答えた時間も消える

**着手(いま始める)**

先延ばしする人にとって、最初の関門は終わらせることではなく、始めることです。そこで、タスクでロックされたときは「完了にする」ではなく「いま始める」を主ボタンにします。

| 場面 | 「今日」のいちばん上に出るもの |
|---|---|
| タスクが理由でロックされた(パスで外している間も同じ) | 主ボタン「いま始める」。その下に、控えめな「もう終わっている」 |
| 「いま始める」を押した | 「作業中」と、押してからの経過時間。主ボタンは「完了にする」に替わる |

- 「いま始める」は、取りかかった時刻を残すだけ。**始めただけでは、ロックは外れない**
- 完了にするとき、取りかかってからの時間(5 分刻み、最短 5 分)を、実際にかかった時間の最初の選択にする。選択肢にも足す。休んだ時間も入るので、本人が選び直せる
- 「いま始める」を押していなければ、見積もりが最初の選択になる。「もう終わっている」は、押さずに完了の確認へ進む
- 目標のような計測の画面は、タスクにはない。「いま始める」が出るのは、そのタスクがいちばん先に片づける理由になっているときだけ

**1行での入力**

タスクの名前の欄に「金曜までにレポート 2時間」のように書くと、締切と見積もりを読み取って提案します。反映するかどうかは本人が決めます。反映すると、名前から日付や時間の部分が取り除かれます。

| 読み取るもの | 書き方の例 |
|---|---|
| かかる時間 | 2時間、1時間半、1時間30分、90分、1.5時間、2h、1h30m、45min |
| 日付 | 今日、明日、明後日、金曜、来週の月曜、10/12、10月12日、today、tomorrow、Friday、next Mon |
| 時刻 | 18時、午後6時半、9時30分、23:59、6:30pm、6pm |

- 日本語と英語の、決まった書き方だけを読む。読み取れなかった部分は、名前に残す
- 日付だけなら、時刻は 23:59 にする。時刻だけで、今日のその時刻を過ぎていれば、明日にする
- 曜日は、次に来るその曜日(今日がその曜日なら今日)。月日で、もう過ぎた日付は、来年として読む
- 読み取った時間は、選べる範囲(5〜600 分、5 分刻み)に合わせる
- 何も書かなければ、締切の初期値は明日の 23:59、見積もりの初期値は 60 分

着手リミットに使う倍率は、次のように決まります。

| 設定 | 倍率 |
|---|---|
| **自動**(初期値) | 直近 10 件の完了タスクについて「実際 ÷ 見積もり」を求め、その中央値を使う。実績が 3 件に満たない間は 1.5。1.0〜3.0 の範囲に収める |
| 固定 | 1 / 1.25 / 1.5 / 2 から選ぶ |

- 自動でも、1.0 より小さくはしない。見積もりより早く終わる人でも、着手リミットを後ろへはずらさない
- 倍率が変わると、未完了のタスクすべての着手リミットが動く
- いまの倍率は、設定、タスクの編集、振り返りの画面に表示する
- タスクの編集画面では、着手リミットの下に、その時刻になる理由を出す。「見積もりは2時間ですが、これまで約1.5倍かかっているので、3時間を見込んでいます」のように、見積もり、倍率、見込んでいる時間を並べる。黙って前倒しすると、理不尽に見えるため
- タスクごとに「見積もりどおりの時刻にする」を選べる。選ぶと、そのタスクには倍率を掛けない。前倒しが合わないタスクを、個別に戻すためのもの。ほかのタスクには影響しない

### 3.3 ロックが外れたあと

- 理由がすべて消えたら、その日は自由に使える
- 新しい理由(別のタスクの着手リミットなど)が来たら、またロックされる

### 3.4 パス(非常口)

- 1回につき15分、ロックが外れる
- 1週間(月曜始まり)に使える回数の初期値は2回。設定で0〜5回
- 使えるのはロック中だけ
- 使うときは、ボタンを3秒押し続ける。うっかり使わせないため
- 今週使った回数は振り返りに表示する

### 3.5 抜け道と、その扱い

| 抜け道 | 現在の扱い |
|---|---|
| 完了ボタンを押すだけで外れる | 実際にかかった時間を1問聞くのみ。使ってみてから対策を考える |
| 目標の量を減らす、今日の曜日を外す | 未対応。変更はすぐに効く。「変更は翌日から有効」にする案がある |
| タスクの締切を延ばす、見積もりを減らす、「見積もりどおりの時刻にする」に切り替える | 未対応。変更はすぐに効き、着手リミットが後ろへずれてロックが外れる |
| 目標を削除する、削除して作り直す | 削除は長押しを要求するのみ。作り直すと、その日はロックされない。未対応 |
| タスクを取り下げて外す | 取り下げは長押しを要求し、振り返りに回数(直近30日)を出す |
| タスクを削除して外す | 削除は長押しを要求するのみ。取り下げの回数には数えない。未対応 |
| 設定を緩める(パスの回数を増やす、倍率を下げる) | 未対応。変更はすぐに効く |
| 設定アプリで権限を切る | 防げない(iOS の仕様) |

## 4. 余裕の表示(このアプリの中心)

ホーム画面の主役は ToDo の一覧ではなく、**次のロックまでの余裕**です。

- ロックされていないとき: 余裕を秒まで数えて出し、次に何が何時にロックの理由になるかを添える。残り1時間を切ると、色で緊張を伝える
- ロック中: 何を終えれば外れるかと、残りの量を出す。ほかにも理由があれば件数を出す
- 片づけたあとの見通し: いちばん上のボタンの下に、「終えると、次のロックは◯時まで延びます」「終えると、今日はもうロックされません」と出す。いま動く理由を、具体的な時刻で見せるため。ほかにも理由が残っていて、終えてもロックが外れないときは出さない
- パスを使っている間: パスが切れるまでの残り時間を出す
- 今日これ以上ロックの予定がないとき: 「今日は自由」と、次のロックの時刻を出す
- まだ何も登録していないとき: 最初の目標を足すよう促す
- 「今日のロック予報」を、時刻順の1本で出す(下の表)
- 「これからの7日」を、天気予報のように並べる。日ごとに、最初のロックの時刻と、荒れ具合を出す。荒れ具合は、予定なし、いつもの目標だけ、締切が1件、締切が2件以上、の4段階。何も登録していないときは出さない
- 「この先の締切」に、明日以降に着手リミットが来るタスクを、近い順に 4 件まで出す。今日のぶんはロック予報にあるので、ここには出さない

「今日のロック予報」は、以前は「ロック予報」と「今日の分」の2枚に分かれていました。同じものを二度見せていたので、1本にまとめました。

| 行 | 出すもの | その場でできること |
|---|---|---|
| 目標(今日が「やる曜日」のもの) | ロックが始まる時刻(1日の開始からなら「朝から」)、進み具合の輪、「やった量 / 今日の分」 | 計測を始める。行を押すと編集 |
| タスク(今日のうちに着手リミットが来る、または過ぎたもの) | 着手リミットの時刻、締切 | 完了にする。行を押すと編集 |
| 今日完了にしたタスク | 取り消し線を付けて残す | 行を押すと編集 |

- まだ片づいていないものを、時刻の早い順に上へ並べる。片づいたものは下に寄せる。次に危ないものが、いつもいちばん上に来る
- いまロックの理由になっているもの、これからなるもの、片づいたものを、印と濃さで区別する
- 作った当日の目標は、時刻を出さず、進み具合の代わりに「ロックは明日から」と出す

余裕を見せる狙いは、ロックされてから動くのではなく、**ロックされる前に片づける**行動を引き出すことです。理想は、一度もロックされない日が続くことです。

アプリの外にも出します。

| 手段 | 内容 |
|---|---|
| ウィジェット | 次のロックまでの余裕。ホーム画面(小、中)とロック画面(長方形、1行)。ロック中は、何を終えれば外れるかを出す。中(横長)は、右側に今日のロック予報を、まだ片づいていないものから 3 件まで出す。押すと、いちばん先にやるべき目標の計測が開く。アプリで目標やタスクを変えるたびに、内容を作り直す |
| コントロールセンターのボタン | 押すと、いちばん先にやるべき目標の計測が開く。ロック画面やアクションボタンにも置ける |
| 通知 | ロックの 30 分前と、ロックが始まったとき。これから始まるロックのうち、近い順に 8 件まで。目標やタスクを変えるたびに、予約を作り直す。許可は初回設定を終えた直後に求める |
| Live Activity | 集中の計測の残り時間。ロック画面と Dynamic Island。**余裕は出さない**(余裕はウィジェットに出す) |

ウィジェットとコントロールセンターのボタンが開く「いちばん先にやるべき目標」は、ロックの理由になっている目標です。なければ、まだ終えていない今日の分。どちらもなければ、「今日」の画面を開きます。アプリが起動していない状態から押しても開きます。初回設定の途中や、ほかの画面を開いているときは、割り込みません。

当初は Live Activity にも余裕を出す想定でしたが、いまの実装は集中の計測だけです。余裕を Live Activity にも出すかどうかは決めていません。調査では、Live Activity は長時間出し続けられない可能性があるとされています([リスクの調査](../research/risks.md) 1。未確認)。

## 5. 画面

| 画面 | 内容 |
|---|---|
| 今日 | 余裕、片づけたあとの見通し、今日のロック予報(今日の分とタスクを時刻順に1本)、これからの7日、この先の締切(4件まで) |
| 集中 | 全画面の計測。残り時間、目標名、終了時の演出 |

| 設定 | ロックするアプリ(許可と選択)、見積もりに掛ける倍率、パスの回数、1日の開始時刻、はじめの説明をもう一度見る |
| 初回設定 | 導入、仕組みの説明、最初の目標、スクリーンタイムの許可とロックするアプリの選択、完了。終えた直後に通知の許可を求める |
| ロック画面(シールド) | ロックされたアプリを開いたときに OS が出す画面。いちばん先に片づけるものの名前と、今日の分の残りを出す(未検証) |

## 6. 演出の方針

ゲームやショート動画に慣れた人が相手なので、地味な管理画面にはしません。

- 力を入れる瞬間: 今日の分を終えたとき、ロックが外れたとき、ロックされる前にタスクを終えたとき
- 使うもの: 動き、振動、色の変化、数字の増減。今日の分を終えた瞬間は、波紋、光の粒、振動で伝える(「視差効果を減らす」が有効なら、動きは出さない)
- 使わないもの: ガチャ的な報酬、連続記録が途切れる不安をあおる表現、罪悪感をあおる文言

このアプリ自体がもう1つの依存先になることは避けます。開いている時間が短いほど良いアプリです。

## 8. 今は入れないもの

- 書籍のバーコード登録
- カレンダー連携、Canvas などの学習管理システムとの連携
- 繰り返しタスク
- クイズや単語カードによる解除
- 複数端末の同期

## 9. 未検証の部分

次の機能は実機と有料の開発者登録がないと確かめられないため、コードはあるが動作未確認です。

- スクリーンタイムの許可を求める流れ
- ロックするアプリを選ぶ画面(OS の選択画面)と、選んだ内容の保存
- スクリーンタイム API による実際のロック(シールドの設定と解除)
- アプリを閉じている間の、時刻どおりのロック開始(予約と、起こされてロックを掛け直す拡張機能)
- アプリを閉じている間の、ロックの解除。日付が変わったとき(前の日のロックを外す)と、計測が今日の分に達したとき
- ロック画面(シールド)の文言と色を決める拡張機能
- Family Controls の権限を付けた、実機向けの署名

次のものは、コードもまだありません。

- ロック画面(シールド)のボタンを押したときの動き

実機で確かめる項目は[公開前の確認事項](../engineering/release-checklist.md)にあります。

「実装済み」は、コードがあるという意味です。「テストあり」は、自動のテストが通っているという意味で、実機で確かめたという意味ではありません。テストの件数は、判定と計算が 67、画面のロジックが 193、保存が 8、画面の操作(UI テスト)が 30 です。2026-10-09 時点で、すべて通っています。UI テストが撮った画面は、[画面の一覧](../screenshots/README.md)にあります。

次の制限も分かっています。詳しくは[設計の全体像](../engineering/architecture.md) 8 にあります。

- 明日の朝に始まる目標のロックは、その日になるまで通知の対象に入らない
- 「いま始める」は、「今日」のいちばん上にしか出ない。ロック予報の行や「予定」の画面からは始められない。始めたことの取り消しもできない
- 取りかかってからの時間には上限がない。前の日に始めたタスクを完了にすると、1日ぶんの時間が最初に選ばれる
- 着手リミットの理由の説明は、実績がまだないとき(1.5 倍を仮に使っている)や、倍率を固定しているときも、「これまで約◯倍かかっているので」と出る
- 集中の計測中にアプリを開いていると、ウィジェットや通知の作り直しが 15 秒ごとに起きる(不具合。表示は正しいが、無駄が多い)
