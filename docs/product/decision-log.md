# 決定の記録

仕様に関する決定と、その理由を時系列で残します。新しい決定は末尾に足します。

「決めた人」が Claude の項目は、オーナーの確認がまだ済んでいないものです。レビューで覆して構いません。

## 2026-10-09 仕様相談

オーナー(山田)との相談で決まったこと。

| 決定 | 理由 | 決めた人 |
|---|---|---|
| iPhone アプリとして作り、App Store で公開する | 自分で使い、他の人にも届けたい | オーナー |
| 対象は、時間がゲームや動画に流れてしまう人 | オーナー自身の課題。対象がはっきりする | オーナー |
| ゲームや動画は、今日の分が終わるまで強くロックする | 「気づいたら1時間」を止めるには、開く瞬間に割り込む必要がある | オーナー |
| 今日の分を終えたら、その日は自由 | 終えたあとまで縛ると、アプリごと消される | オーナー |
| 締切のあるタスクも扱い、着手リミットを過ぎたらロックする | ぎりぎりでも手を付けない人には、締切前の実力行使が効く | オーナー |
| 着手リミットは所要時間から計算する | 入力が「どれくらいかかるか」だけで済む | Claude |
| 今日の分の量と、目標の配分は利用者が設定する。いつでも変更できる | 人によって合う量が違う | オーナー |
| 逃げ道は、ある程度用意する | 体調不良や急用に対応するため | オーナー |
| 振り返りはグラフで見せる | 積み上がりが見えると続く | オーナー |
| 書籍のバーコード登録は入れない | 管理の手間を増やさない | オーナー |
| カレンダー連携、Canvas 連携は保留 | 核ではない | オーナー |
| 日本語と英語に対応する | 公開時の対象を広げる | オーナー |
| Live Activity、ウィジェットなど、最近の API を積極的に使う | 体験を良くし、アプリの外に出る | オーナー |
| 有料の Apple Developer Program に登録する | スクリーンタイム API に必要 | オーナー |
| 実装コストより UI/UX を優先する | 対象の人は、地味な画面では使い続けない | オーナー |

## 2026-10-09 実装開始時に Claude が決めたこと

| 決定 | 理由 |
|---|---|
| 仮の名前を Yoyu(余裕)とする | 中心となる数字「次のロックまでの余裕」から。短く、英語圏でも発音できる |
| ホームの主役を「余裕」と「ロック予報」にする | 既存のタスク型ブロックアプリは、ロックを今かかっているかどうかでしか見せない。先の見通しを見せれば、ロックされる前に動ける |
| 目標のロック開始は「朝から」を初期値にし、時刻指定も選べる | オーナーは強いロックを希望。ただし朝から使えないと続かない人もいる。目標もタスクも「リミットを過ぎたらロック」という1つの考え方にそろう |
| 完了は自己申告で、確認を1回挟む | 紙の教材では検証できない。まず使ってから対策する |
| パスは15分、週2回まで、3秒の長押し | 逃げ道は必要だが、楽に使えてはいけない |
| タスクの取り下げは長押しを要求し、回数を振り返りに出す | 取り下げが抜け道になるため |
| 1日の区切りは朝4時 | 夜更かしした日の深夜を前日として扱う |
| 余裕係数の初期値は 1.0 | まず単純に。見積もりが甘い人は設定で上げる |
| 連続記録(ストリーク)は作らない | 途切れる不安で縛る手法は、依存を助けるアプリの趣旨に反する |
| ガチャ的な報酬は使わない | 同上 |
| アカウント登録なし、端末内保存のみ | 始めるまでの手間を減らす。個人情報も預からない |
