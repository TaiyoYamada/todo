いま何ができていて、次に何をするかをまとめた文書です。優先順位は Claude の提案で、オーナーの確認はまだです。

| 区分 | 内容 |

## オーナーに決めてほしいこと

## 次にやること

上から順に、効果が大きいと考えるものです。

### 1. 実機での確認(オーナーの作業が必要)

1. Apple Developer Program に登録する
2. 実機でスクリーンタイム API の動作を確かめる(確認項目は公開前の確認事項にある)
3. Family Controls の配布用の権限を Apple に申請する。承認まで数日から2か月かかるので、動いた時点ですぐ出す

### 2. タスクにも計測を付ける

いまは、タスクは「完了にする」を押すだけです。目標と同じように計測を始められるようにします。

- 先延ばしする人に必要なのは、終わらせることより先に、始めること
- 実際にかかった時間が自動で分かるので、完了のときに聞かなくて済む
- 自己申告だけに頼らなくなる

### 3. 今日の画面の整理

- 「ロック予報」と「今日の分」は同じものを二度見せている。時刻順の1本にまとめる
- 片づいたものは下に寄せ、次に危ないものだけを目立たせる

### 4. 学習の見せ方

- 着手リミットが動いた理由を、その場で説明する(「前回は見積もりの1.6倍かかったので」)
- 「今回は見積もりどおりにする」を選べるようにする

### 5. その先の候補

| 案 | 内容 | 出どころ |
|---|---|---|
| 間に合わない確率 | 固定の時刻ではなく、実績から「間に合わない確率」を出してロックを決める | 別のモデルの批評 |
| カレンダー連携 | 予定の詰まり具合を読んで、今日の分を自動で増減する | オーナーとの相談(保留中) |
| 端末内 AI | 目標を小さな一歩に分ける。Foundation Models を使う | オーナーの希望(最近の API) |
| iCloud 同期 | 機種変更時の引き継ぎ。SQLiteData に仕組みがある | 設計時の検討 |
| 繰り返しタスク | 毎週の課題など | 仕様の「今は入れないもの」 |

## やらないと決めたこと

| 案 | 理由 |
|---|---|
| 連続記録(ストリーク) | 途切れる不安で縛る手法は、このアプリの趣旨に反する |
| ガチャ的な報酬 | 同上 |
| クイズで解除 | 既存アプリが多数あり、院試の勉強のような内容には合わない |
| 振り返りのグラフと演出を削る | 別のモデルは削るよう勧めたが、オーナーが明示的に望んでいる |
| カウントダウンの秒を消す | 時計と紛れるという指摘はあるが、動いている数字が目を引く効果を優先した。見出しで区別している |
