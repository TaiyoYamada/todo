## 次にやること

上から順に、効果が大きいと考えるものです。

### 1. 実機での確認(オーナーの作業が必要)

1. Apple Developer Program に登録する
2. 実機でスクリーンタイム API の動作を確かめる(確認項目は公開前の確認事項にある)
3. Family Controls の配布用の権限を Apple に申請する。承認まで数日から2か月かかるので、動いた時点ですぐ出す

### 2. 実機で確かめる前に直すもの

コードを読んで分かっている不具合です。実機がなくても直せます。詳しくは[設計の全体像](../engineering/architecture.md) 8 にあります。

- 集中の計測中、ウィジェット、予約、通知の作り直しが 15 秒ごとに起きている。今日の分に達する時刻が、計算のたびに 1 秒未満ずれるため
- ロック画面(シールド)のボタンを押したときの動きを決める
- 設定アプリで許可を切られたときの動きを決める

### 3. タスクの着手の残り

「いま始める」は入りましたが、当初の案(目標と同じように計測する)のうち、できているのは一部です。

| 当初の狙い | いま | 残り |
|---|---|---|
| 終わらせることより先に、始めることを促す | タスクでロックされたときの主ボタンが「いま始める」になった | 「いま始める」が出るのは、「今日」のいちばん上だけ。ロック予報の行や「予定」の画面、ロックされる前には出ない |
| 実際にかかった時間が自動で分かり、完了のときに聞かなくて済む | 取りかかってからの時間を、最初の選択にする | 質問は残っている。休んだ時間も入るので、本人の確認が要る。計測の画面、一時停止、Live Activity はない |
| 自己申告だけに頼らない | 変わっていない | 完了は、いまも自己申告 |

ほかに、次の点が残っています。

- 始めたことを取り消せない
- 取りかかってからの時間に上限がない。前の日に始めたタスクでは、1日ぶんの時間が最初に選ばれる
- 完了にしたタスクを未完了に戻しても、取りかかった時刻は残る

### 4. 学習の見せ方の残り

理由の説明と、タスクごとの切り替えは入りました。残っているのは次の点です。

- 説明が出るのは、タスクの編集画面だけ。倍率が変わって着手リミットが動いたときに、その場で知らせる仕組みはない
- 「見積もりどおりの時刻にする」は、ロック中でもすぐに効く。抜け道として塞ぐかどうかを決める

### 5. その先の候補

| 案 | 内容 | 出どころ |
|---|---|---|
| 間に合わない確率 | 固定の時刻ではなく、実績から「間に合わない確率」を出してロックを決める | 別のモデルの批評 |
| カレンダー連携 | 予定の詰まり具合を読んで、今日の分を自動で増減する | オーナーとの相談(保留中) |
| 端末内 AI | 目標を小さな一歩に分ける。Foundation Models を使う | オーナーの希望(最近の API) |
| iCloud 同期 | 機種変更時の引き継ぎ。SQLiteData に仕組みがある | 設計時の検討 |
| 繰り返しタスク | 毎週の課題など | 仕様の「今は入れないもの」 |

## やらないと決めたこと

| 案 | 理由 |
|---|---|
| 連続記録(ストリーク) | 途切れる不安で縛る手法は、このアプリの趣旨に反する |
| ガチャ的な報酬 | 同上 |
| クイズで解除 | 既存アプリが多数あり、院試の勉強のような内容には合わない |
| 振り返りのグラフと演出を削る | 別のモデルは削るよう勧めたが、オーナーが明示的に望んでいる |
| カウントダウンの秒を消す | 時計と紛れるという指摘はあるが、動いている数字が目を引く効果を優先した。見出しで区別している |
