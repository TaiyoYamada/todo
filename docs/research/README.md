# 市場・競合・事業モデルの調査

調査日: 2026-10-09

対象: スマホを使いすぎる学生・若者向けの iPhone アプリ（仮称「Yoyu / 余裕」）。長期目標の1日ノルマと締め切りタスクに連動して、選んだアプリを Screen Time API でロックし、ロックまでの余裕を「ロック予報」として見せる。

## 要約

1. 「1日ノルマが終わるまでロック」は新規性がない。日本の TodoLock とあとスマ、海外の Unrot（米国評価 約5.7万件）など、同じ仕組みが多数ある。
2. 「締め切り − 所要時間から自動ロック」と「ロックまでの余裕を主画面に出す」は、調べた範囲では見つからなかった。ただし Proc、Structured × one sec、Finiti が隣接しており、真似は容易。
3. 「ドパガキ」向けという訴求は、あとスマとドパロックが2026年夏に先に使っている。
4. 「Yoyu」は日本の App Store に同名・同音が3本あり、1本は同じカテゴリで発想も近い。改名を勧める（第一候補は Lockcast）。
5. 需要は実在する。Opal は DAU 100万超・ARR 1,000万ドルで、DAU の3分の2が学生と報じられている（未監査）。日本の高校生の平日ネット利用は平均6時間44分（こども家庭庁）。
6. ただし学生は払わない。Opal は無料化で課金転換率が 20% から 9% に下がった。日本の学生だけでは売上は小さく、英語圏と社会人の資格学習層が要る。
7. 推奨はフリーミアム。ロックと予報は無料、件数・取り込み・統計を Pro（年 ¥2,900、買い切り ¥6,800）にする。
8. 最大の技術リスクは、ロック開始を担う API の不安定さ。配布エンタイトルメントの承認も数日〜2か月と読めない。
9. 設計上の最大の穴は見積もりの甘さ。人は所要時間を短く見積もるので、「ぎりぎりの時点」でロックしても間に合わない。実績からの自動補正を中核に据えるべき。
10. 先に「予報だけ」の版を出せば、承認を待たずに中心仮説（予報で行動が変わるか）を確かめられる。

## 読み方

- 評価件数、公開日、対応 OS は 2026-10-09 に Apple の iTunes Lookup API で取得した値。
- 競合の機能は各社の App Store 掲載文に基づく。実機での確認はしていない。
- 「未確認」は、裏づけが取れなかったか、二次情報しかない記述。「推測」は、仮定を置いた試算。
- 名称の確認は簡易なもので、商標の法的な調査ではない。

## 調べきれなかったこと

- Android、中国・韓国のストア、未公開の開発中アプリ
- ブロッカー系アプリの継続率・削除率
- 子どもアカウント（13〜17歳）の端末で、本人の認可によるロックが動くか
- 設定からの許可取り消しを iOS 26.4 以降で防げるか
- 日本の大学で使われる学習管理システムからの課題取り込みの可否
- J-PlatPat での商標検索
